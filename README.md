# HDEG

> 面向日语 ASMR（RJ 音声作品）的**端到端字幕翻译工具** —— 以官方台本为 **Ground Truth**，让 ASR 字幕翻译告别「垃圾进、垃圾出」。

An end-to-end subtitle translation toolkit for Japanese ASMR audio works, built around the **official scriptbook as the single source of truth** to systematically correct the inherent errors of automatic speech recognition.

`Python` · `DeepSeek` · `Faster-Whisper` · `PyMuPDF` · `pyopenjtalk` · `Electron`

---

## 核心优势

### 🎯 台本即真理：治本，不治标

日语 ASMR 的语音识别（ASR）**天然脆弱**——耳语、喘息、抽泣、背景音/SE、方言、气声，机器几乎不可能准确转录。大多数工具的做法是「ASR 出来什么就翻译什么」，结果就是垃圾进、垃圾出。

HDEG 换了一条路：**把随作品发售的官方台本当作权威依据（Ground Truth）**。

- ASR 与台本冲突时，一律以台本为准——角色名、固定称呼、身体部位、剧情一致性、拟声词全部以台本校正。
- 翻译时整份台本作为 `<scriptbook>` 参考注入提示词；每条 ASR 行还**附上对应的台本原文（sb）与置信度（sb_conf）**。
- 这把一个「提升 ASR 精度」几乎无解的问题，转化成了「用权威文本纠错」的可解问题——从源头修正转录错误，而非在错误文本上二次创作。

### 🧠 全格式台本提取，竖排 PDF 也不怕

- TXT 自动探测编码（UTF-8 / Shift-JIS / cp932）；PDF 直接文本提取。
- **PDF 自动检测横排/竖排布局并重排**——日文台本大量使用竖排排版，普通提取器会打乱行序，HDEG 专门处理。
- **LLM 识别台本文件**：从一堆 readme / クレジット / 特典 / あとがき 里挑出真正的台本，判断是否已按音轨预分割，并完成「文件 → 音轨」映射；LLM 失败自动回退正则关键词识别。

### ⚡ 台本分割：免费优先，能省则省

台本可能是一个包含全部音轨的整体文件，需要按音轨切分。HDEG 用**两级定位 + 回退链**，把成本压到最低：

1. **FZ 锚点法（本地免费）**：用每条音轨的 ASR 前几句在台本中逐行模糊匹配，算出每轨的近似锚点。
   实测中位偏差仅 **1.5 行**（9 轨作品），10 部作品的测试中 7 部可直接靠 FZ 定位；典型耗时 10 轨 × 700 行 ≈ 30s。
2. **LLM 精定位（低价 Flash 模型）**：FZ 锚点把搜索范围**缩窄到 ±50 行**，再让 LLM 用行号区间精确定位——既省 token 又提高准确率，而非全文大海捞针。
3. **正则兜底**：LLM 失败时回退 `split_scriptbook_regex`。

预分割台本（一个文件 = 一个音轨）则直接本地清洗，**零 LLM 调用**。

> 温度分层：台本分割 / 识别 / 世界观分析用 `temperature=0.1` 保证精确；翻译用较高温度保留口语化与语气。

### 🔗 ASR ↔ 台本 多对多区间对齐

ASR 与台本不是一行对一行，而是**多对多**（ASR 可能合并、拆分、漏识、即兴发挥）。HDEG 不做粗暴的 1:1 匹配：

- 把整轨 ASR 与整轨台本各自拼成字符串，做**字符级序列对齐**（借助 `pyopenjtalk` 的汉字→假名读音匹配，未安装时自动回退纯假名/汉字比较），顺序保持、禁止回溯。
- 每条 ASR 行得到一个【台本行区间 `[lo..hi]`】与置信度；**低置信行不附台本**，避免插值猜测误导翻译。

### 🧪 实战打磨的翻译提示词

内置一整套经过验证的提示词，覆盖 ASR 纠错与本地化的全部痛点：

- **ASR 纠错四步工作流**：可信度审查 → 上下文一致性修复 → 中文翻译 → 译文回检（防日文汉字照搬、防语义矛盾）。
- **角色名统一规则**：术语表最高优先，禁止别名/变体。
- **成人术语直译规范**：明确禁止儿童化 / 卖萌 / 含糊表达，要求直白准确。
- **翻译忠实度约束**：保留语气、喘息、短句，禁止文艺化 / 书面化 / 自行扩写。
- **JSON 输入输出格式强制**：index 精确对齐，自带截断 / 损坏 JSON 自动修复。
- **缓存友好结构**：`<scriptbook>` 固定前缀（同作品所有音轨共享 → 命中 API 提示词缓存）+ `<asr>` 可变后缀。

### 💰 三层成本控制

| 层 | 手段 |
| --- | --- |
| 模型分层 | 台本分割 / 清洗走低价 Flash 模型，翻译才用主力模型 |
| 缓存复用 | 台本分割结果缓存到 `_scriptbook_clean.json` / `_split_tracks/`，重复运行零 LLM 调用；术语 / alias / 世界观只加载已有缓存，默认不重复自动分析 |
| 峰谷调度 | 转录完成后延迟翻译到空闲时段执行（高峰 09:00–12:00 / 14:00–18:00 北京时间，空闲价 = 高峰价 **50%**），进程内自动等待到点续跑 |

统一 **Token 追踪**：每次调用记录 命中/未命中/输出 token，按作品（RJ 目录）汇总真实费用。

### 🧩 术语 · 世界观 · 一致性体系

- **术语表（terms）** 与 **ASR 误识别参考表（alias）**：角色名、物品、身体部位称呼全文统一。
- **世界观分析（LLM）**：抽取角色 / 性格 / 场景 / 特殊术语，自动注入术语表。
- **变体轨继承**：`（ルームver）` 等带修饰词的音轨，自动继承主轨台本。
- **本地一致性检查器（零 LLM）**：扫描已翻译字幕，找出同一日文词译法不一致、术语表定义了却未使用、翻译与术语表偏离等问题。

### 🛠 面向失败的健壮工程

- **层层回退**：LLM → 正则、JSON 解析 → 自动修复、`pyopenjtalk` → 纯假名比较、转录超时看门狗（10 分钟无输出自动判死）。
- **多字幕格式**：LRC / SRT / VTT，日文原版自动留档 `.ja.lrc`，翻译后自动同步 SRT / VTT。
- **本地优先**：API Key 为空时仅执行本地转录（infer.exe），照常可用；RTX 50 系显卡自动切换 `compute_type=float16`。
- **双层分发**：PyInstaller 打包 + Electron 桌面界面（拖拽目录、翻译审核、术语编辑、一致性检查）。

## 为什么需要它

日语 ASMR 字幕翻译的两大痛点：

1. **转录即错**：耳语、喘息、BGM、方言叠加下，ASR 的错误率高到离谱，直接翻译等于在错误之上叠错误。
2. **术语混乱**：同一部作品里角色名、身体部位、设定用语前后不一致，观感割裂。

HDEG 的答案很直接——**别再和 ASR 死磕，直接读官方台本**。官方台本随作品发售，是台词的权威原文；HDEG 把「识别 + 分割 + 对齐 + 纠错 + 翻译」做成一条全自动流水线，你只需要把一个作品目录拖进来。

## 工作流程

```text
┌─────────────┐   ┌──────────────────────┐   ┌─────────────────────────┐
│  音频/视频   │ → │  ① 本地转录 infer.exe │ → │ ② 台本识别（LLM/正则）   │
│  + 官方台本  │   │  （生成 .ja.lrc 留档）  │   │    提取 + 分割 + 清洗     │
└─────────────┘   └──────────────────────┘   └────────────┬────────────┘
                                                          ↓
   ┌───────────────────────────────────────────────────────────────┐
   │ ③ 术语/alias/世界观 加载（缓存优先，缺失才 LLM 分析）           │
   │ ④ 台本对齐：ASR ↔ 台本 多对多区间对齐（sb + 置信度）            │
   │ ⑤ 翻译：术语 + 世界观 + 台本参考 + ASR 逐轨 → DeepSeek API       │
   │ ⑥ 写回 .lrc，同步 .srt/.vtt，.ja.lrc 日文留档                    │
   └───────────────────────────────────────────────────────────────┘
```

（可选：开启 `delay_translate_to_offpeak` 后，步骤 ②–⑥ 的 LLM 调用会等空闲时段自动开始，享受 5 折费率。）

## 快速开始

### 环境要求

- Python 3.10+
- DeepSeek API Key（当前仅支持 DeepSeek API）
- 可运行的海南鸡转录模型（`infer.exe` + 模型，放入 `转录模型/`）

### 安装

```bash
pip install -r requirements.txt
```

> `pyopenjtalk` 在 Windows 上可能需要预编译 wheel，安装失败时项目会自动回退到纯假名/汉字比较，不影响主流程。

### 配置

```bash
cp config.example.json config.json
```

编辑 `config.json`：

- `api.key` — 填入你的 DeepSeek API Key
- `transcription.infer_exe` — 转录程序路径
- `app.delay_translate_to_offpeak` — 转录完成后延迟翻译到空闲时段执行（峰谷定价：高峰 09:00–12:00、14:00–18:00 北京时间，其余空闲，空闲价 = 高峰价 50%）。`true` 时若转录完成正处高峰，程序会倒计时等待到空闲再自动翻译

### 运行

```bash
python main.py <作品目录>
```

或将作品文件夹直接拖到 `翻译_debug.bat`。

### 输出

- 作品目录下生成中文 `.lrc`，日文原版留档为 `.ja.lrc`
- 台本清洗结果导出为 `_scriptbook_clean.json` 与 `_split_tracks/`
- 命令行末尾输出 Token 用量 / 费用统计

## 技术架构

分层设计，职责清晰：

| 层 | 模块 | 职责 |
| --- | --- | --- |
| 管道层 | `pipeline/orchestrator.py` | 端到端编排（转录 → 台本 → 术语 → 翻译 → 报告） |
| 核心层 | `core/` | 纯逻辑：台本解析、版面分析、文本分块、一致性检查 |
| 引擎层 | `engines/` | LLM 引擎：翻译、台本清洗/分割、台本对齐、术语、世界观、OCR |
| IO 适配层 | `io_adapter/` | 配置加载、文件扫描、字幕读写 |
| 工具层 | `utils/` | 统一输出、Token 追踪、文本过滤、峰谷调度时间侦测 |

## 目录结构

```text
main.py                    # 命令行入口
pipeline/orchestrator.py   # 端到端管道编排（转录 → 台本 → 翻译）
core/                      # 台本解析、PDF 提取、版面分析
engines/                   # 翻译引擎、台本清洗/分割/对齐、术语、世界观
io_adapter/                # 配置加载、文件扫描、字幕读写
utils/                     # 输出、Token 追踪、文本过滤、峰谷调度
build_release.py           # 打包脚本
main.spec                  # PyInstaller 配置
config.example.json        # 配置模板（复制为 config.json 使用）
```
